# Day — проверка кандидата 21 ноября 2026

## Что вошло

- Календарь главной, планировщик день/неделя/месяц/год, фотографии дат; календарь продуктивности с подтверждёнными порогами 100%, 50–99%, менее 50%. Пустые и будущие дни нейтральны, закрытые дни используют снимок итогов.
- Автосохранение аккаунта и приватных фотографий персонализации, включая аватар, фон, навигацию, блоки и даты. Локальная очередь переживает отсутствие сети, конфликт ревизий не перезаписывает записи автоматически.
- Защита ожидающих загрузки фотографий при автоматическом получении новой облачной копии; локальная очистка не может удалить облачные записи последующим автосохранением, защитный флаг сохраняется после перезагрузки.
- Обновлённый дневник питания, помощник бытовых мер, быстрые веса и расчёт на порцию/100 г. AI-черновик требует проверки; известные нутриенты сохраняются, неизвестные поля обязательны и остаются пустыми, настоящий ноль не теряется.
- Gemini для фотографий еды по серверному ключу, без автоматического перехода на платного провайдера. Лимиты, ошибка квоты, проверка входа, RU/EN/IT. Текстовый Day AI использует отдельную интеграцию OpenAI.
- Dockerfile переведён на Node 24 LTS, все `.env*` исключены из build context. Сам Docker-контейнер не собирался: Docker CLI на устройстве отсутствует.

## Реальный Gemini

Ключ хранится в серверном `.env.local`, файл имеет права 0600 и исключён `.gitignore`. Ключ не скопирован в документацию или клиентский код.

Короткий текстовый запрос к выбранной модели завершился HTTP 200. Затем живой image+JSON запрос сначала выявил `400 INVALID_ARGUMENT`: ограничивающая JSON-грамматика была слишком сложной. После упрощения схемы настоящий `geminiFoodResponse` обработал искусственный PNG 64 × 64 и вернул валидное `{ingredients:[]}`. Отсутствие еды на тестовом изображении обработано корректно. Границы количества/веса/нутриентов остались в серверной Zod-проверке.

Этот запрос проверяет image input и формат ответа; он не подтверждает точность распознавания настоящей еды или авторизованный пользовательский сценарий целиком. Пользовательские фотографии в smoke-запросы не отправлялись. Бесплатность зависит от тарифа и квоты Google-проекта; биллинг проекта не проверялся. Ключ, отправленный в чат, владельцу следует заменить.

## Supabase и оставшиеся проверки

Миграция `day_private_photos` применена к `czoybiitgacfpwfuxfak`: bucket `day-photos` приватный, 5 МБ, JPEG/PNG/WebP/GIF, чтение и вставка ограничены папкой `auth.uid()`. Живая проверка схемы и политик пройдена ранее в этой работе; реальные пользовательские фото через аккаунт не загружались и аккаунты не удалялись.

`npm run release:check -- --strict` вернул **exit 1**: отсутствуют `SUPABASE_SERVICE_ROLE_KEY` для удаления аккаунта и `OPENAI_API_KEY` для текстового чата. Supabase public config и Gemini key заданы. Это незавершённая внешняя конфигурация, а не пройденный релизный gate. Пользовательские изменения Google/email авторизации сохранены; свежий реальный вход ещё не проверен.

Перед публикацией остаются:

- Вход Google/email, подтверждение и восстановление email на целевом домене.
- Два реальных устройства и два аккаунта: записи, фото, смена аккаунта, offline/retry и RLS.
- Реальная фотография еды через вошедший аккаунт, правка порций и сохранение записи.
- Визуальная, мобильная и клавиатурная проверка собранного интерфейса. CUA заблокировал открытие тестовой вкладки политикой доступа; повторов через обходные средства не было. Новые скриншоты не получены.
- Сборка/запуск Docker Node 24, HTTPS, production callback URL, поддержка и фактическая политика обработки данных.
