# Day calendars

Обновить существующие календари без изменения пользовательских доработок входа.

Главная: лента недели с мягко движущимся выделением, количеством задач и фото выбранных дней. Кнопка изображения открывает доступный диалог выбора/замены/удаления картинки с устройства. Планировщик: единый анимированный переключатель День / Неделя / Месяц / Год, реальные даты и задачи; год раскрывается в месяц, дата — в дневной план. Вдохновение: приложенные schedule-calendar, cue-cell-to-card-calendar-expansion и day-picker; сохранить дизайн Day и существующие motion/react, lucide-react.

Прогресс: календарь продуктивности Неделя / Месяц / Год с выбором даты и числом завершённых задач. По умолчанию: 100% — зелёный, 50–99% — жёлтый, <50% — красный; нет задач или будущая дата — нейтрально. Это предложенная граница, пользователь может изменить её в ответе. Закрытые итоги используют сохранённый снимок, чтобы перенос задач не переписывал результат дня. Дополнительное представление в духе FocusCity: изометрические здания по выполненным задачам, а не выдуманным сессиям фокуса. Цвет и высота имеют явную легенду.

Картинки гостя хранятся локально в IndexedDB. По дополнительному запросу владельца добавлено облачное сохранение для аккаунта: приватный Supabase Storage bucket day-photos, путь userId/photoId, только свой каталог, файл до 5 МБ. Сначала загрузить файл, затем включить его UUID в облачный manifest и настройки. На другом устройстве файл скачивается приватно в локальный кэш. При отсутствии сети локальный файл сохраняется, очередь повторяет загрузку. Сохранение локальной ссылки должно пройти до удаления прежнего локального файла; смена аккаунта/сброс прерывают незавершённые операции. Старые копии данных продолжают загружаться. Все новые тексты RU/EN/IT; клавиатура, экранные дикторы, тёмная тема, мобильный экран и reduced motion поддерживаются.

Настройки/записи аккаунта автоматически сохраняются с задержкой 900 мс. Чистое устройство подхватывает более новую облачную ревизию при входе/возврате. Незагруженные локальные изменения не затираются; при конфликте ревизий требуется явное восстановление с резервной копией. Локальный сброс сам по себе не очищает облако. JSON-экспорт не содержит бинарных фото или ссылок, принадлежащих чужому аккаунту; при JSON-импорте текущие локальные фото сохраняются. Удаление аккаунта предварительно удаляет его приватные файлы.

Подход: адаптировать присланные компоненты к единой модели дат и реальным данным. Отдельные демо с фиктивными событиями не подходят для рабочего планировщика. Новые зависимости не требуются; фотографии пользовательские, стоковые изображения не нужны.
